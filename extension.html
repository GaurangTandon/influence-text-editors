Influencing an editor from an extension

The same seven buttons and the same five editors, with the influencing code running as an extension's content script instead of in the page. This is the case that decides whether any of the recipe survives an isolated world.

What is actually being tested

An extension's content script runs in an isolated world: the same DOM as the page, a separate JavaScript realm with its own copy of every constructor. It can read the editor, focus it, set its selection and dispatch events into it. What it cannot do is add a property to an object the page can see.

That matters here because the recipe's two hardest-won steps are both own properties written onto an event with Object.defineProperty: shadowing getTargetRanges() (the only way to supply a target range in WebKit) and shadowing clipboardData with a real DataTransfer (the only way to supply a clipboard in Firefox).

  1. A second content script is injected into the page's own world ("world": "MAIN") with the identical code. That is the control: if MAIN reproduces the same-document results and ISOLATED does not, the world is the variable.
  2. Both worlds answer a small set of probes directly, in whichever realm the editor lives — instanceof DataTransfer only means something in the editor's own realm.
  3. isTrusted is measured for completeness. Nothing can change it: no realm, no privilege, no extension API.

Install the extension to run this

The page below works without the extension — it renders the recorded results — but the buttons only dispatch once a content script is listening.

  1. From a clone of this repository, build it: npm install && npm run build
  2. Chrome, Edge or any Chromium browser: chrome://extensions → Developer mode → Load unpacked → choose vendor/extension/.
  3. Firefox: about:debugging#/runtime/this-firefox → Load Temporary Add-on… → choose vendor/extension/manifest.json.
  4. Reload this page. The status line should report both worlds.
